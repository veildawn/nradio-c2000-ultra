# C2000 Ultra：补齐「双系统切换」+「5G 蜂窝/SIM」LuCI 前端并实测进固件

## Context
固件后端已具备：`c2000-bootswitch`（status/to-factory/to-openwrt，CRC32 安全校验）与 `mt5700` 守护进程（三路 SIM sim1/sim2/esim/auto 切换、运营商 APN 自动配置、UCI `mt5700` 配置）。但 LuCI 无对应页面，只能 SSH 操作。目标：新增两个 LuCI 页面，**SSH 上设备部署实测通过**，并让 ImageBuilder（FILES overlay）与源码（apply.py）两条构建路径自动携带。

## 步骤

**0. SSH 通道**：用 expect + 密码把本机 ed25519 公钥写入 `/etc/dropbear/authorized_keys`，之后免密 `root@192.168.1.1`；确认设备现状（board、bootswitch status、luci-base 实际安装的 `fs.js` API 签名、mt5700 状态、AT 端口）。

**1. 新增 LuCI 应用（全部在 `board/files/`，随现有注入机制进固件）**：
- `usr/sbin/mt5700-status`：board_name 守卫；与 mt5700 守护/netifd 避让（`mt5700.lock` 非阻塞、wwan pending 跳过 AT）；单次 gcom 会话批量 AT（CPIN?/CIMI/ICCID/COPS?/CSQ/HCSQ?/CEREG?/C5GREG?/CHIPTEMP?）+ 15s 缓存；ubus 取 wwan_4/wwan_6 IP；jshn 输出 JSON
- `etc/gcom/mt5700-status.gcom`：批量 AT 采集脚本
- `usr/share/rpcd/acl.d/luci-app-nradio-c2000.json`：exec `c2000-bootswitch`/`mt5700-status`/`/sbin/reboot`（luci-base ACL 不含 reboot，需自带）+ uci `mt5700` 读写
- `usr/share/luci/menu.d/luci-app-nradio-c2000.json`：**网络 → 5G 蜂窝**、**系统 → 双系统切换**
- `www/luci-static/resources/view/nradio/modem.js`：状态卡片（USB 速率/AT 口/网卡、SIM 状态+槽位+IMSI/ICCID、运营商/注册/RAT、CSQ+HCSQ 信号、模组温度、wwan IP，10s 轮询）+ 设置表单（enabled/sim_slot/apn/usb3_retrain/fix_nvram/thermal_guard/check_interval，注明由守护进程 ≤30s 生效）
- `www/luci-static/resources/view/nradio/bootswitch.js`：当前启动目标 + 「切换到原厂系统」确认弹窗（说明 boot_from_sd=0、TF 卡数据不动、原厂 Web 可切回）+ 成功后可选立即重启；目标已设但未重启时提供「取消切换」
- 中文文案直接内置（非 luci-app-* 包，不触发 workflow 的 i18n 断言）

**2. 设备实测**（scp 到 /tmp 安装、重启 rpcd 生效 ACL）：
- `mt5700-status` 输出合法 JSON 且字段真实；`to-openwrt` 幂等分支真实执行验证 exec 链路；`to-factory` 实写测试**先征得同意**再执行并立即切回
- curl 登录 LuCI 验证两个页面 200；浏览器（browser-use）打开页面截图验证渲染、表单提交落盘 uci、30s 内守护进程应用（SLOT_STAMP 变化）

**3. 固件化收尾**：
- `.github/workflows/imagebuilder.yml`：lint 增加 `! -name '*.json' ! -name '*.js'`；release notes 补两个页面说明
- `STATUS.md` 新增 LuCI 前端小节
- 本地下载官方 IB 构建一次 sysupgrade 验证打包（若可行）
- 开分支 commit → push → 触发 Actions 构建（是否发 Release 到时确认）

## 关键风险与对策
- AT 口并发：复用守护进程锁 + wwan pending 避让 + 缓存戳，UI 轮询不冲击拨号
- 源码路径会把 app 文件放进 filogic base-files（其他板构建带上但运行时守卫），与现有 board 脚本同策略
